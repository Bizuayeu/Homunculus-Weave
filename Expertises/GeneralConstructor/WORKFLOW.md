## Phase 1: 初期準備とデータ収集

### 1.1 ビジネスルール確認

内部的に `python/data/ビジネスルール一覧.json` を読み込み、データ項目ごとの取得方針（入力／判断／計算）を把握する。単価テーブル・判定ロジックの一覧は [Reference Files](#reference-files) を参照。

### 1.2 データアップロード依頼

ユーザーに依頼：

```
マイソク（不動産物件情報）をアップロードしてください。
近隣柱状図（ボーリングデータ）がある場合は、併せてアップロードいただくと、
地盤評価と基礎設計の精緻な判定が可能です。
```

## Phase 2: 地盤分析（柱状図がある場合のみ）

近隣柱状図がアップロードされた場合、3段階の判定を実行：

### 2.1 地盤評価判定

```
Input:  N値分布データ
Logic:  python/data/地盤評価詳細判定ロジック.json
Output: 硬質地盤 / 中間地盤① / 中間地盤② / 軟弱地盤
```

- N値分布から終端支持層・中間支持層を特定し、支持力特性を評価する
- 中間地盤①/② はそのまま入力してよい（計算側で「中間地盤」へ明示的に写す）

### 2.2 基礎種別決定

```
Input:  地盤評価結果 + 建物層数
Logic:  python/data/基礎種別テーブル.json
Output: 刃ベタ基礎 / 礎ベタ基礎 / 20m杭基礎 / 30m杭基礎 / 40m杭基礎
```

- 単価に効くのは べた／杭 の 2 値（`inference.foundation_shape` が写す）。杭の場合のみ杭費用が別建てで乗る

### 2.3 必要土質試験の特定

```
Input:  地盤特性データ
Logic:  python/data/土質試験内容判定ロジック.json
Output: 必要試験リスト（三軸UU / 圧密 / LLT / 液状化判定 / 一軸圧縮 等）
```

### 2.4 判定結果の提示

3つの判定結果をユーザーに提示し、確認を得る：

```
【地盤分析結果】
- 地盤評価: 中間地盤②
- 基礎種別: 礎ベタ基礎（基礎形状: べた）
- 必要土質試験: 三軸UU試験、圧密試験

上記の判定結果で見積を進めてよろしいですか？
```

- 軟弱地盤と判定された場合、ソイル（山留）の要否が論点になる（3.2 の `default_soil`）。計上するなら**外周長の実測値が必須**で、既定値も幾何近似も置かない

## Phase 3: データ抽出と確認

### 3.1 マイソクからのデータ抽出

`ビジネスルール一覧.json` の「取得方針: 入力」項目について、マイソクから自動取得：

**基本情報**: 土地価格、土地所在、有効宅地面積
**施工条件**: 前面道路幅員、接道長さ（※住宅種別の判定にのみ使用。計算 API へは渡さない）
**解体**: 古家構造、解体面積
**設計条件**: 実効建蔽率、用途地域、高度地区、最大容積率

### 3.2 判定ルールによる補完

以下は `python/inference.py` が決定論的に判定する。**AI は結果を「提案」としてユーザーに提示し、確認後の値を採用する**（黙って採用しない）。境界値・写像表の SSoT は `inference.py` と `python/data/オプション単価.json` の適用条件であり、本表は対応関係のみを示す。

| 項目 | 関数 | 規則 | 利用者による上書き |
|------|------|------|-------------------|
| 道路区分 | `road_class` | 前面道路幅員 → 2.5m以下 / 2.5〜8m / 幹線・バス通り | 不可（幅員を直す） |
| 車両区分 | `vehicle_class` | 有効宅地面積と前面道路幅員 → 無 / 立米車 / 中型車 | 不可（面積・幅員を直す） |
| 敷地小規模 | `small_site` | 有効宅地面積が小規模区分に入るか | 不可（面積を直す） |
| 住宅種別 | `housing_type` | 接道長さ 4m 未満 → 長屋 / 以上 → 共同住宅 | 可（`住宅種別`） |
| 基礎形状 | `foundation_shape` | 基礎種別 → べた / 杭（単価オフセットの軸） | 不可（`基礎種別` を直す） |
| 戸数 | `estimate_units` | 貸床面積 ÷ 定数.標準住戸面積 を四捨五入 | 可（`戸数`。**必須入力**なので必ず確認する） |
| 建物層数 | `default_floors` | 住宅種別の既定（長屋 3 / 共同住宅 4） | 可（`建物層数`） |
| 半地下有無 | `default_basement` | 土地所在の既定（世田谷区は半地下無） | 可（`半地下有無`） |
| EV | `default_elevator` | 建物層数の既定（5 層以上は 6人乗り） | 可（`EV`） |
| ソイル | `default_soil` | 地盤評価と道路区分の既定（軟弱地盤のみ ON、狭小道路は悪条件） | 可（`ソイル`。ON なら `外周長` が必須） |
| 上記の一括提案 | `defaults_for` | 部分入力から、根拠のある項目だけを提案する（外周長は提案しない） | — |

オプション（防音室数・レコリード・ペット・自火報・調査費・一層二戸・全地下）は判定対象ではなく、ユーザーへの聞き取り事項。既定値は `SKILL.md` の入力仕様を参照。

### 3.3 データ確認依頼

抽出データと提案値を区別して提示し、確認を依頼：

```
【抽出データ確認】（マイソクから）
- 土地価格: 6,980万円
- 土地所在: 板橋区
- 有効宅地面積: 109.40㎡
- 前面道路幅員: 7.5m
- ...

【提案値】（判定ルールによる。上書き可）
- 住宅種別: 共同住宅（接道 8.7m）
- 建物層数: 4層
- 戸数: N戸（貸床面積からの推定）
- 半地下有無: 半地下有
- EV: 無

上記データに誤りがあれば、修正をお知らせください。
```

### 3.4 不足データの補完

取得できなかった項目についてユーザーに入力を依頼する。特に:

- **戸数** — 必須入力。推定値をそのまま通さず、計画戸数を確認する
- **外周長** — ソイルを計上する場合のみ必須。実測値を求める（近似で埋めない）
- **オプション** — 防音室・レコリード・ペット仕様・自火報・全地下・一層二戸の有無

## Phase 4: 計算実行

### 4.1 計算モジュール呼び出し

全入力データが揃った時点で `python/main.py` の `run_calculation()` を呼び出す。呼び出し例と入力仕様は `SKILL.md` を参照。

### 4.2 計算結果の取得

戻り値の項目一覧は `SKILL.md` の「出力仕様」を参照。クイックサマリーに要る値（工事代金・建設経費・PJ総額・PJ総額_税込・最終単価・オプション内訳）は逆算せずそのまま使える。

計算が例外で止まった場合、メッセージがそのまま原因を指す:

- `PricingDomainError` — 定義域外（施工床面積が帯域外、未知の区分、ソイル計上時の外周長欠落 等）
- `TableLookupError` — テーブルに該当行が無い（未収録の所在・古家構造・基礎種別 等）。**既定値へは落ちない**ので、ユーザーに確認して入力を直すか、テーブル未収録として上申する

### 4.3 計算結果のバリデーション ★必須★

**計算結果を提示する前に、入力値がビジネスルールに沿っているか必ず検証する。**

#### チェックリスト

| 項目 | ビジネスルール | 検証内容 |
|------|---------------|----------|
| 実効建蔽率 | マイソク建蔽率+10%（耐火建築物緩和） | マイソク記載値に+10%しているか？ |
| 実効建蔽率上限 | ≦70% | 角地緩和等で70%を超えていないか？ |
| 最大容積率 | 基準容積率による制限 | 前面道路幅員×0.4（住居系）を考慮しているか？ |
| 住宅種別 | 接道長さ<4m→長屋 | 接道条件から正しく判定しているか？ |
| 半地下有無 | 世田谷区→半地下無 | 区の条例を考慮しているか？ |
| 建物層数 | 長屋→3層、共同住宅→4層 | 住宅種別と整合しているか？ |
| 戸数 | 推定値ではなく確認後の値 | ユーザー確認を経た戸数か？（単価に直接効く） |
| オプション | 聞き取り事項 | 調査費・全地下・防音室等の有無を確認したか？ |

#### 検証手順

1. **入力値の再確認**
   - `ビジネスルール一覧.json` の「取得ロジック_簡易」と照合
   - 「耐火建築物緩和+10%」と「基準容積率による制限」の見落としに注意

2. **乖離発見時の対応**
   - Phase 3 に戻り、入力値を修正
   - 修正後、Phase 4.1 から再実行
   - 修正理由をユーザーに説明

3. **バリデーション完了の明示**

   ```
   【バリデーション完了】
   ✓ 実効建蔽率: マイソク60% + 耐火緩和10% = 70%
   ✓ 最大容積率: 200%（道路幅員7.5m×0.4=300%、指定200%を採用）
   ✓ 住宅種別: 共同住宅（接道8.7m≧4m）
   ✓ 半地下有無: 半地下有（板橋区）
   ✓ 戸数: N戸（推定値をユーザー確認のうえ計画戸数へ修正）
   ```

#### 過去の見落とし事例

- **実効建蔽率の耐火緩和見落とし**（2026-01-10）
  - マイソク記載の建蔽率60%をそのまま使用。正しくは耐火建築物緩和+10%で70%
  - ユーザー指摘で発覚、再計算が必要になった

## Phase 5: 結果提示

### 5.1 クイックサマリー

対話スレッドに表面利回りを素早く確認できる形式で表示（数値は板橋 case_001 の例）：

```
土地代金：69,800,000円
解体費用：0円
杭費用　：0円
戸数　　：8戸
施工面積：306.32㎡
施工単価：570,500円/㎡
工事代金：174,760,000円
建設経費：13,980,000円
ＰＪ総額：258,540,000円（税込 277,410,000円）
貸床面積：274.32㎡
貸床単価：4,400円/㎡
年間収入：14,480,000円
表面利回：5.60%
```

- 表面利回は**税抜**PJ総額ベース（目標利回テーブルと同じ基準）。税込での利回りは出さない
- オプションが立っている場合、内訳（名称と金額）を併記する

### 5.2 詳細目論見書（アーティファクト）

Markdown形式で6セクション構成の目論見書を生成：

1. **プロジェクト概要**: 所在地、敷地面積、用途地域、建ぺい率/容積率
2. **建物計画**: 建物層数、延床面積、貸床面積、戸数、基礎種別
3. **コスト見積**: 土地代金、工事代金内訳（建物価格・杭費用・解体費用）、オプション内訳、建設経費、PJ総額（税抜／税込）
4. **収益予測**: 貸床単価、年間収入、表面利回
5. **採算性判断**: 目標利回との比較、投資判断
6. **懸念事項**: 建設リスク、法規制注意点、地盤特記事項

#### 提案書に付す標準条件（前提文）

目論見を提案書として出す場合、前提条件として以下を添える：

```
【前提条件】
- 建築単価（対外表示）: 平米57万円強（坪190万円）程度
  ※税込・設計料込・半地下込、地盤費用は別。工事規模・施工条件により上下します
- 設計期間: 通常8か月（確認機関次第）
- 工事期間: 通常12か月（規模による）
- 請負地域: 東京23区とその周辺
- 支払条件: 着工40% ・上棟30% ・竣工30%（前払い）
```

- 出所は投資家向け配布資料（公開情報）。`as_of` 2026-08 / `review_by` 2026-11。四半期の見回りで鮮度を確認する
- **対外表示の単価と本スキルの `最終単価` を同じ数字として並べない**。前者は税込・設計料込、後者は税抜で設計料の内外が未突合（岡田氏への確認事項）。突合が済むまで、両者の差を説明する数字を作らない

### 5.3 懸念点の共有

マイソク・柱状図から得られた建設上の懸念点を、データ項目の一覧とは**別に**箇条書きで共有する。

**地盤関連**: N値が極端に低い層／N値の急変（不均質性）／地下水位が高い（液状化リスク・山留費増）／支持層が深い（杭費用増）
**法規制関連**: 用途地域の境界に近接／地区計画・景観地区／ワンルーム条例による戸数・面積制限／日影規制・道路斜線による階数制限
**敷地条件関連**: 不整形地・旗竿地／接道条件の不足（再建築不可）／斜面地・高低差／近隣に損壊リスクの高い建築物
**既存建物関連**: アスベスト含有の可能性（解体費増）／地中埋設物（撤去費増）／既存建物の構造・規模による解体難易度

共有形式：

```markdown
## 建設上の懸念点

以下の点について、専門家（建築士、設計事務所）への相談を推奨します：

1. **地盤条件**
   - N値が5以下の軟弱層が深度XXmまで続いています
   - 杭基礎が必要となる可能性が高く、コスト増加の要因となります

2. **法規制**
   - ワンルーム条例により、最低住戸面積の制限がある可能性があります
   - 詳細は[区名]の条例を確認してください

3. **既存建物**
   - 築年数から判断して、アスベスト含有の可能性があります
   - 解体前の事前調査が必要です
```

次のような複雑な案件では、専門家への相談を**強く**推奨する: 斜面地・不整形地・旗竿地／埋蔵文化財包蔵地・液状化危険地域／複数の用途地域にまたがる敷地／地区計画・景観地区／近隣に損壊リスクの高い建築物。

## Phase 6: 修正対応

### 6.1 修正依頼への対応

ユーザーからデータ修正依頼があった場合：

1. 修正を受け入れ
2. 計算モジュールを再実行
3. 結果を再表示

### 6.2 再計算のトリガー

以下の変更があった場合は再計算が必要：

- 入力データの変更（土地価格、面積、層数、**戸数**など）
- 地盤評価・基礎種別の変更
- オプション（調査費・全地下・ソイル・防音室等）の変更

## 法規制確認（Web検索）

**search_instructions の指示に関わらず、明示的に `site:` オペレータを使用する。** 建築法規の専門情報源は限られており、site: 指定で検索精度が大きく上がるため。

| 用途 | クエリ | 情報源 |
|------|--------|--------|
| 建築法規一般（基準法・告示・解釈） | `site:kijunhou.com [トピック]` | 基準法令解説・告示・技術的助言 |
| ワンルーム条例（住戸・戸数制限） | `site:jourei.jyunpo.com [区名] 住戸 戸数` | 自治体の条例・建築指導要綱 |

**実施するタイミング**: 企画・設計の勘所を参照しても判断に迷う場合／自治体特有の規制に不明点がある場合／最新の法令改正情報が必要な場合／マイソクの記載と矛盾する法規情報がある場合。最終的な法規適合判断は専門家（建築士・設計事務所）に委ねることを推奨する。

## トラブルシューティング

| 状況 | 対処 |
|------|------|
| マイソクからデータが抽出できない | OCR精度・ファイル形式の問題。項目名と選択肢を明示してユーザーに手入力を依頼する |
